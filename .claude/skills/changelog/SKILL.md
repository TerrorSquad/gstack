# Updating the user-facing changelog

There are **two changelogs — don't confuse them.**

- `CHANGELOG.md` (repo root) is auto-generated by **release-please** from
  conventional commits. Developer-facing, versioned, **never hand-edit** — the
  release PR owns it and overwrites it.
- The **user-facing** "What's new" feed is `app/utils/changelog.ts`
  (`CHANGELOG_ENTRIES`), rendered at `/changelog` (`app/pages/changelog.vue`).
  Hand-curated, dated entries, no version numbers.

## When to add an entry

Only for **genuinely user-visible** changes: a new page or flow, or a visible
change to an existing action. **Not** for tests, migrations, i18n plumbing,
refactors, or analytics. Add the entry as part of the same change — a
user-facing commit isn't done until its "What's new" entry is written.

## How

Edit `app/utils/changelog.ts` and prepend an entry (newest first):

```ts
{
  date: '2026-07-18', // ISO YYYY-MM-DD
  title: 'Short human title',
  highlights: [
    feature('What the user can now do, in plain language.'),
    fix('What visibly got fixed.'),
  ],
},
```

- **One entry per date.** If an entry for today already exists, fold new
  highlights into it — the page prints the date per entry, so two same-date
  entries render the date twice.
- Write in the user's language, not commit-speak. Add every user-facing string
  to both `i18n/locales/sr.json` and `en.json` if you introduce new keys.
- No version numbers — those are for developers in `CHANGELOG.md`.
